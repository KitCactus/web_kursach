# Как устроен проект: cafe management system

---

## Общая структура

```
web_kursovoe/
├── cafe/cafe/          ← Бэкенд (Spring Boot, Java)
└── cafe-client/        ← Фронтенд (Angular, TypeScript)
```

Фронт и бэк — два отдельных приложения. Фронт работает на порту 4200 (в dev), бэк на 8080. Общаются через HTTP запросы (REST API). В prod-сборке фронт компилируется в статические файлы и раздаётся прямо с бэка на порту 8080.

### entity/ — таблицы базы данных

Каждый класс = одна таблица в PostgreSQL. Аннотация `@Entity` говорит Hibernate: "создай таблицу из этого класса". Hibernate — это инструмент который сам генерирует SQL за тебя, не надо писать CREATE TABLE вручную.

```java
@Entity
@Table(name = "users")
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;           // столбец id, автоинкремент

    @Column(unique = true)
    private String username;   // столбец username, уникальный

    @ManyToMany               // связь многие-ко-многим
    private List<Role> roles;  // через таблицу user_roles
}
```

Таблицы в БД:
- `users` — сотрудники кафе
- `roles` — роли (ROLE_ADMIN, ROLE_USER)
- `user_roles` — связка пользователей и ролей
- `menu_items` — блюда в меню
- `orders` — заказы
- `order_items` — позиции в заказе

---

### repository/ — интерфейс для работы с БД

Это **паттерн Repository** — прячет SQL за обычными Java-методами. Ты объявляешь только интерфейс, реализацию пишет Spring сам.

```java
public interface UserRepository extends JpaRepository<User, Long> {
    Optional<User> findByUsername(String username);
    // Spring читает название метода и сам генерирует:
    // SELECT * FROM users WHERE username = ?
}
```

`JpaRepository<User, Long>` даёт бесплатно методы: `findAll()`, `findById()`, `save()`, `delete()` и др.

Для сложных запросов используют аннотацию `@Query`:
```java
@Query("SELECT u FROM User u WHERE u.isActive = true")
List<User> findAllActive();
```

---

### service/ — бизнес-логика

Сервис решает ЧТО делать: проверки, расчёты, обращения к репозиторию. Controller не должен знать про БД — он спрашивает Service, а Service спрашивает Repository.

```
Controller → Service → Repository → БД
```

---

### controller/ — точки входа HTTP

Каждый метод = один URL. Аннотации определяют тип запроса:

```java
@RestController
@RequestMapping("/api/menu")
public class MenuController {

    @GetMapping           // GET  /api/menu
    public List<MenuItemDto> getAll() { ... }

    @PostMapping          // POST /api/menu
    public MenuItemDto create(...) { ... }

    @PutMapping("/{id}")  // PUT  /api/menu/5
    public MenuItemDto update(...) { ... }

    @DeleteMapping("/{id}") // DELETE /api/menu/5
    public void delete(...) { ... }
}
```

---

### dto/ — объекты передачи данных

DTO (Data Transfer Object) — то что реально летит по сети в JSON. Entity — внутренний объект с паролем, служебными полями. DTO — только то что нужно отдать клиенту.

Например `UserDto` содержит `id`, `username`, `fullName`, `role` — но **не содержит** `password`.

---

### config/SecurityConfig.java — кто что может

Два уровня защиты:

**1. webSecurityCustomizer** — полностью исключает из Security (даже не проверяет):
```java
web.ignoring().requestMatchers("/uploads/**");
// картинки доступны всем без логина
```

**2. authorizeHttpRequests** — правила для остальных URL:
```java
.requestMatchers("/api/auth/login").permitAll()           // вход — всем
.requestMatchers(HttpMethod.GET, "/api/menu").hasAnyRole("ADMIN", "USER")  // просмотр меню — любой залогиненный
.requestMatchers(HttpMethod.DELETE, "/api/menu/*").hasRole("ADMIN")        // удаление — только ADMIN
.anyRequest().authenticated()                             // всё остальное — требует логина
```

### config/WebConfig.java — статические файлы и SPA-роутинг

```java
// Указывает Spring где лежат загруженные фотографии
registry.addResourceHandler("/uploads/**")
        .addResourceLocations("file:D:/web_kursovoe/cafe/cafe/uploads/");

// чтобы Angular сам обработал URL типа /menu, /dashboard
registry.addViewController("/{spring:\\w+}")
        .setViewName("forward:/index.html");
```

## Аутентификация и авторизация

**Аутентификация** = "ты кто?" (проверка логина/пароля)
**Авторизация** = "тебе можно это делать?" (проверка роли)

### Как это работает пошагово:

```
1. Фронт кодирует: btoa("admin:123") → "YWRtaW46MTIz"
2. Фронт шлёт заголовок: Authorization: Basic YWRtaW46MTIz
3. Spring Security перехватывает запрос
4. Декодирует Base64 → "admin:123"
5. CustomUserDetailsService.loadUserByUsername("admin")
   └── UserRepository.findByUsername("admin") → находит в БД
6. BCrypt проверяет: совпадает ли "123" с хешем в БД
7. Если совпало → проверяет роль по правилам из SecurityConfig
8. Если роль подходит → пропускает в Controller
```

### BCrypt — хеширование паролей

Пароль нельзя хранить в открытом виде. BCrypt превращает "123" в:
```
$2a$10$N9qo8uLOickgx2ZMRZoMye...
```
Обратно расшифровать нельзя — только проверить. Поэтому даже если БД утечёт, пароли не скомпрометированы.

### Stateless

Сервер **не хранит сессии**. При каждом запросе фронт заново присылает логин:пароль в заголовке. Сервер каждый раз проверяет по БД. Плюс: легко масштабировать, нет проблем с синхронизацией сессий. Минус: немного медленнее (запрос к БД на каждый запрос).

### services/ — HTTP запросы

Сервис — посредник между компонентом и бэкендом. Компонент не делает HTTP напрямую:

```typescript
// menu.service.ts
getMenuItems(): Observable<MenuItem[]> {
  return this.http.get<MenuItem[]>(`${apiUrl}/api/menu`);
}

// menu.component.ts
this.menuService.getMenuItems().subscribe(items => {
  this.items = items;  // получили данные, записали в компонент
});
```

---

### Observable, pipe, tap, map

**Observable** — поток данных который придёт в будущем. HTTP-запрос возвращает Observable потому что ответ придёт не сразу.

```typescript
// Без Observable (синхронно — так нельзя с HTTP):
const data = http.get('/api/menu');  // данных ещё нет!

// С Observable (асинхронно):
http.get('/api/menu').subscribe(data => {
  // вот теперь данные есть
});
```

**pipe** — труба через которую данные проходят и трансформируются:
```typescript
http.post('/auth/login', body).pipe(
  map(response => /* преобразуй данные */),
  tap(user => /* побочный эффект, данные не меняет */)
)
```

**map** — преобразует данные (как Array.map). Например превращает `AuthResponse` в `User`.

**tap** — выполняет побочный эффект (логирование, сохранение в sessionStorage) не меняя данные. В `auth.service.ts`:
```typescript
login(username, password).pipe(
  map(response => {
    return { id: response.id, username: response.username, role: response.role };
  }),
  tap(user => {
    sessionStorage.setItem('authToken', btoa(`${username}:${password}`));
    // сохранили токен, но user не изменился
  })
)
```

---

### BehaviorSubject — реактивное состояние

```typescript
private currentUserSubject = new BehaviorSubject<User | null>(null);
public currentUser$ = this.currentUserSubject.asObservable();
```

`BehaviorSubject` хранит текущее значение и оповещает всех подписчиков при изменении. Когда логинишься:
```typescript
this.currentUserSubject.next(user);
// все компоненты которые подписаны на currentUser$
// автоматически получают нового пользователя
```

---

### guards/ — защита маршрутов на фронте

Три guard-а в `app.routes.ts`:

```typescript
{ path: 'login',       canActivate: [loginRedirectGuard] }
// если уже залогинен → /dashboard

{ path: 'dashboard',   canActivate: [authGuard] }
{ path: 'menu',        canActivate: [authGuard] }
// если не залогинен → /login

{ path: 'admin/staff', canActivate: [authGuard, adminGuard] }
// если не залогинен → /login
// если не ADMIN → /dashboard
```

Важно: guard-ы на фронте — это **удобство**, не безопасность. Настоящая защита — на бэкенде в SecurityConfig. Даже если обойти guard и открыть страницу, бэкенд всё равно не отдаст данные без нужной роли.

---

### interceptors/auth.interceptor.ts — автозаголовок

Вместо того чтобы в каждом сервисе вручную добавлять `Authorization`, интерсептор перехватывает все HTTP запросы автоматически:

```typescript
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = sessionStorage.getItem('authToken');
  if (token && req.url.includes('/api/')) {
    const headers = req.headers.set('Authorization', `Basic ${token}`);
    return next(req.clone({ headers }));
  }
  return next(req);
};
```

### environments/ — конфиг

```typescript
// environment.ts (dev — ng serve)
export const environment = {
  production: false,
  apiUrl: 'http://localhost:8080'
};

// environment.prod.ts (prod — ng build)
export const environment = {
  production: true,
  apiUrl: ''  // пустая строка = тот же хост что открыт в браузере
};
```

В prod запросы идут как `/api/menu` (относительный путь) — на тот же сервер.
В dev запросы идут как `http://localhost:8080/api/menu` (абсолютный путь) — на бэк.

## Полный путь запроса

**Пример: открываешь страницу `/menu`**

```
1. Angular проверяет authGuard
   └── есть ли currentUser в sessionStorage?
   └── нет → редирект на /login
   └── есть → пропускаем

2. MenuComponent инициализируется, вызывает:
   menuService.getMenuItems()

3. MenuService делает:
   GET http://localhost:8080/api/menu

4. auth.interceptor перехватывает и добавляет:
   Authorization: Basic YWRtaW46MTIz

5. Запрос летит на бэк

6. Spring Security перехватывает:
   - Декодирует Base64 → admin:123
   - CustomUserDetailsService находит admin в БД
   - BCrypt проверяет пароль
   - Проверяет: ADMIN/USER может GET /api/menu? → да

7. MenuController.getAllMenuItems() вызывается
   └── MenuService.getAllMenuItems()
   └── MenuRepository.findAll()
   └── SQL: SELECT * FROM menu_items
   └── Hibernate преобразует результат в List<MenuItem>
   └── Service преобразует в List<MenuItemDto>
   └── Controller возвращает JSON

8. Angular получает JSON
   └── subscribe(items => this.items = items)
   └── шаблон рендерит список блюд
```

## Способы защиты в проекте

| Защита | Где | Что делает |
|--------|-----|------------|
| HTTP Basic Auth | Каждый запрос | Логин:пароль в заголовке |
| BCrypt | БД, SecurityConfig | Пароли хранятся хешем |
| Role-based access | SecurityConfig | ADMIN и USER имеют разные права |
| Guards | app.routes.ts | Нельзя открыть страницу без роли |
| CORS | SecurityConfig | Бэк принимает запросы только с localhost:4200/8080 |
| webSecurityCustomizer | SecurityConfig | Картинки публичны, остальное защищено |

## Ключевые аннотации Spring Boot

| Аннотация | Смысл |
|-----------|-------|
| `@RestController` | Класс принимает HTTP запросы и возвращает JSON |
| `@Service` | Класс содержит бизнес-логику |
| `@Repository` | Класс работает с БД |
| `@Entity` | Класс = таблица в БД |
| `@Autowired` | Spring сам передаст зависимость (внедрение зависимостей) |
| `@GetMapping` | Метод обрабатывает GET запрос |
| `@PostMapping` | Метод обрабатывает POST запрос |
| `@Value` | Читает значение из application.properties |
